## What is an External Version Identifier?

When an application developer submits an iOS build through App Store Connect, Apple's ingestion and DRM signing pipeline generates an immutable, monotonically increasing 64-bit integer index:

- In Storefront XML/JSON manifests: `externalVersionIdentifier`
- In legacy iTunes property lists: `appExtVrsId`

Unlike `CFBundleShortVersionString` (e.g. `13.90.0`) or `CFBundleVersion` (e.g. `142`), which are arbitrary strings defined at the developer's discretion, the **external version identifier** is strictly generated by Apple's servers at ingestion time.

---

## Observing Metadata in the Ingestion Pipeline

Using `ipatool get-version-metadata`, researchers can query the App Store metadata endpoint to inspect:

```json
{
  "externalVersionID": "885041606",
  "displayVersion": "13.90.0",
  "releaseDate": "2026-04-28T19:28:24Z",
  "success": true
}
```

### Key Properties

1. **Monotonic Progression**: Newer builds almost always receive higher integer IDs than older builds.
2. **Immutable History**: Even after an app version is removed from the public App Store listing, Apple's edge storage retains the package associated with that `externalVersionIdentifier` as long as developer distribution rights remain valid.
3. **Regional Integrity**: Build IDs are identical across regional Storefronts, though regional availability restrictions can prevent downloading specific IDs depending on local regulations or developer geo-restrictions.

## Cataloging Services

To avoid brute-force scanning over the entire numeric space, community databases maintain reverse indices:

- [**IPA File Zone**](https://ipafilezone.st/): Complete mapping between display versions and external version identifiers.
- [**armconverter.com**](https://armconverter.com/decryptedappstore): Decrypted binary analysis and bundle metadata.
